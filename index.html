Unidad Didáctica: Validación de Documentos — JSON Schema vs XML Schema (XSD)

1. Introducción a los Esquemas de Validación

Tanto en XML como en JSON, un esquema es un documento especial que actúa como un contrato o plantilla formal. Define las reglas que determinan si una estructura de datos es válida o no.

Criterio JSON Schema XML Schema (XSD)
Formato del esquema Documento escrito en sintaxis JSON. Documento escrito en sintaxis XML.
Objetivo Validar archivos de datos JSON (.json). Validar documentos XML (.xml).
Control de Tipos de Datos Sencillo (string, number, integer, boolean, object, array, null). Muy amplio y estricto (xs:string, xs:integer, xs:date, xs:decimal, etc.).
Comportamiento por defecto Permite claves no definidas en el esquema salvo que se restrinja. Strict por defecto; solo permite los elementos especificados en la secuencia.

2. JSON Schema: Conceptos y Sintaxis

JSON Schema permite definir tipos de datos, restricciones numéricas, expresiones regulares para cadenas y obligatoriedad de propiedades en un objeto JSON.

Propiedades principales de un JSON Schema

  • $schema: Especifica la versión de la especificación JSON Schema (p. ej., Draft 07 o 2020-12).
  • title y description: Documentación aclaratoria del esquema (no afectan a la validación).
  • type: Tipo de dato permitido (object, array, string, number, integer, boolean, null).
  • properties: Objeto que define las claves permitidas y la estructura requerida para cada una.
  • required: Array de cadenas con las claves obligatorias en el objeto validado.
  • additionalProperties: Booleano (false para prohibir campos extra no declarados en properties).
  • minimum / maximum / exclusiveMinimum: Restricciones numéricas.
  • items: Define el tipo y la estructura de los elementos de un array.

Ejemplo Práctico en JSON Schema

{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "Producto",
  "description": "Esquema para un producto en el catálogo",
  "type": "object",
  "properties": {
    "id": {
      "type": "integer",
      "minimum": 1
    },
    "nombre": {
      "type": "string"
    },
    "precio": {
      "type": "number",
      "minimum": 0,
      "exclusiveMinimum": true
    },
    "etiquetas": {
      "type": "array",
      "items": { "type": "string" }
    }
  },
  "required": ["id", "nombre", "precio"],
  "additionalProperties": false
}

3. XML Schema (XSD): Conceptos y Sintaxis

El W3C XML Schema (XSD) se utiliza para definir la estructura de un documento XML mediante etiquetas propias bajo el espacio de nombres http://www.w3.org/2001/XMLSchema.

Conceptos clave en XSD

  • xs:element: Define una etiqueta XML. Puede tener atributo name y type.
  • Tipos Simples (Simple Types): Elementos que solo contienen texto o datos básicos (sin etiquetas secundarias ni atributos).
  • Tipos Complejos (Complex Types): Elementos que contienen otros elementos hijos, atributos o ambos.
  • xs:sequence: Los elementos hijos deben aparecer rigurosamente en el orden especificado.
  • minOccurs y maxOccurs: Controlan la cardinalidad (ej. minOccurs="0" indica que es opcional; maxOccurs="unbounded" permite repetirlo infinitas veces).

Ejemplo Práctico en XSD

<?xml version="1.0" encoding="UTF-8"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">

  <xs:element name="producto">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="id" type="xs:positiveInteger" />
        <xs:element name="nombre" type="xs:string" />
        <xs:element name="precio">
          <xs:simpleType>
            <xs:restriction base="xs:decimal">
              <xs:minExclusive value="0" />
            </xs:restriction>
          </xs:simpleType>
        </xs:element>
        <xs:element name="etiquetas" minOccurs="0">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="etiqueta" type="xs:string" maxOccurs="unbounded" />
            </xs:sequence>
          </xs:complexType>
        </xs:element>
      </xs:sequence>
    </xs:complexType>
  </xs:element>

</xs:schema>

4. Comparativa Práctica Paralela

A continuación se representa la misma información estructurada en JSON y XML con sus respectivas validaciones.

JSON Válido 
{
  "id": 101,
  "nombre": "Teclado Mecánico",
  "precio": 45.99,
  "etiquetas": ["perifericos", "pc"]
}
XML Válido 
<producto>
  <id>101</id>
  <nombre>Teclado Mecánico</nombre>
  <precio>45.99</precio>
  <etiquetas>
    <etiqueta>perifericos</etiqueta>
    <etiqueta>pc</etiqueta>
  </etiquetas>
</producto>

5. Ejercicios Prácticos para el Alumnado

Ejercicio 1: Identificación de Errores en JSON Schema

Dado el esquema JSON de la Sección 2, indica razonadamente si los siguientes documentos son válidos o inválidos:

  1. {"id": 1, "nombre": "Silla Gamer"} → ¿Válido? ¿Por qué?
  2. {"id": 2, "nombre": "Mesa", "precio": -10} → ¿Válido? ¿Por qué?
  3. {"id": 3, "nombre": "Ratón", "precio": 15, "stock": 50} → ¿Válido? ¿Por qué?
Ver soluciones del Ejercicio 1
  1. Inválido: Falta la propiedad requerida precio (definida en el array required).
  2. Inválido: El precio no cumple la restricción exclusiveMinimum: 0 (debe ser estricta y positivamente mayor que 0).
  3. Inválido: Contiene el campo stock que no está declarado y el esquema incluye "additionalProperties": false.

Ejercicio 2: Creación de Esquema XSD

Diseña un esquema XSD para un elemento raíz llamado alumno que contenga:

  • Un elemento nombre (cadena de texto obligatorio).
  • Un elemento edad (entero obligatorio).
  • Un atributo expediente (entero obligatorio en la etiqueta alumno).
Ver solución del Ejercicio 2 
<?xml version="1.0" encoding="UTF-8"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="alumno">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="nombre" type="xs:string" />
        <xs:element name="edad" type="xs:integer" />
      </xs:sequence>
      <xs:attribute name="expediente" type="xs:integer" use="required" />
    </xs:complexType>
  </xs:element>
</xs:schema>
